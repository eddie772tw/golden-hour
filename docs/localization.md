# 新增與維護語系

五個語系都在 [game/i18n](../game/i18n) 目錄。每個檔案匯出完整的「訊息鍵 → 文案」對照。新模組應使用語意鍵，例如 `weapon.progress`、`room.host` 或 `menu.credits`。在原始語言和譯文中使用相同的 `{0}`、`{1}` 參數，順序可依語法調整。英語使用美式拼字；京都日語沿用武器名稱、數據與技術名詞，把對玩家說的操作提示和狀態文案改成京都用語。京都稿仍待母語使用者逐畫面校閱。

1. 在五個語系檔加入同一個鍵。追加第六種語言時，複製完整訊息集，於 `index.js` 登錄語系、選單原文名稱與瀏覽器偏好對應規則。偏好順序為已儲存選擇、瀏覽器語言清單、簡體中文。京都變體需要手動選取。
2. 對 DOM 元素呼叫 `bind(element, "room.host", playerName)`。切換時會用原參數重新格式化；玩家名稱、武器型號、識別碼等是原樣文字。由遊戲自身產生、也需要翻譯的參數可用 `sourceText(value)`。署名、暱稱節點與診斷 JSON 使用 `translate="no"`。輸入欄位的值不在翻譯範圍。
3. 恢復的舊渲染器仍輸出英文或簡體中文。相容層在節點或 `title`、`aria-label`、`placeholder`、`alt` 更新時比對完整來源文案，保存原值供即時切換。若調整英文拼字，保留原始核心的來源別名。載入提示僅接受資源檔內的粗體標籤。新增遊戲介面優先直接綁定鍵。
4. 伺服器遊戲錯誤透過 `{type: "error", code: "error.weapon_locked", params: []}` 傳送。用戶端把錯誤碼映射為本機語系，協定的欄位名稱、房號與數值保持一致。
5. `npm test` 會逐語系檢查鍵、參數和標記，另測瀏覽器回退與動態數據。啟動本機服務後執行 [五語瀏覽器測試](../server/check_languages.py) 和 [混合語系對戰測試](../server/check_browser.py)。翻譯人員應額外檢查長句在手機寬度、控制器導覽與短暫 HUD 提示中的可讀性。
